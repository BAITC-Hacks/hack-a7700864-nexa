# Nexa

Nexa — marketplace бизнес-задач для студенческих команд, созданный для HackAlem AI. Платформа помогает бизнесу превратить свободное описание проблемы в качественный бриф, а командам — найти понятную задачу и предложить решение.

## Проблема

Бизнес часто публикует задачи без контекста, данных и критериев успеха. Студенческие команды тратят время на догадки, а качественные задачи не отличаются от сырых. Nexa делает качество постановки измеримым и поднимает лучше заполненные задачи выше в каталоге.

## Как работает решение

1. Бизнес описывает проблему обычным текстом.
2. AI задаёт ровно три контекстных вопроса.
3. Ответы превращаются в редактируемую карточку без вымышленных фактов.
4. Прозрачная формула рассчитывает рейтинг готовности 0–100.
5. После подтверждения задача публикуется и сортируется в каталоге по рейтингу.
6. Студенческая команда отправляет идею, план, срок и необязательную ссылку на прототип.
7. Бизнес вручную принимает или отклоняет каждое предложение.

## AI-функция

Server-side endpoint `/api/analyze` использует OpenAI Structured Outputs при наличии `OPENAI_API_KEY`. Ответ валидируется через Zod. Ключ никогда не передаётся в браузер.

Без API-ключа или при ошибке API включается детерминированный fallback. Он анализирует уже указанную информацию, выбирает ровно три недостающих аспекта и формирует карточку из описания и ответов. Поэтому полный demo flow работает офлайн.

## Рейтинг готовности

| Критерий | Вес |
| --- | ---: |
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Связь с бизнесом | 10 |
| **Итого** | **100** |

Заполнение оценивается по наличию и содержательности текста. Уровни: 0–39 «Черновик», 40–69 «Рабочая», 70–89 «Готовая», 90–100 «Приоритетная». Низкий рейтинг не скрывает опубликованную задачу.

## Архитектура и стек

- Vinext / React 19 / TypeScript;
- Tailwind CSS и доступные UI-примитивы;
- server-side API routes;
- Cloudflare D1 (SQLite) и Drizzle ORM;
- OpenAI Chat Completions Structured Outputs с валидируемым fallback;
- Zod для AI-ответа и серверная очистка пользовательского ввода.

Исходный код приложения находится в `web/`. API отвечает за AI-анализ, публикацию задач, создание предложений и изменение их статуса. UI поддерживает роли «Бизнес» и «Студент» без сложной авторизации — это осознанное ограничение MVP.

## Database

- `tasks`: исходное описание, структурированные поля, score, уровень, подтверждение и публикация;
- `teams`: название, интересы, навыки и технологии команды;
- `proposals`: связь задачи и команды, идея, план, срок, прототип и ручной статус `PENDING / ACCEPTED / REJECTED`.

Миграции находятся в `web/drizzle/`. При первом открытии пустая база получает 5 демонстрационных задач, 5 команд и 5 предложений.

## Установка

Требуется Node.js 22.13 или новее.

```bash
cd web
npm install
```

Создайте локальный `.env` только при необходимости реального AI:

```bash
cp .env.example .env
```

```env
OPENAI_API_KEY=
```

Пустой ключ допустим — приложение использует fallback. `.env` исключён из Git.

## Запуск

```bash
cd web
npm run dev
```

Проверки перед push:

```bash
npm run typecheck
npm run lint
npm run build
```

## Demo scenario

1. Переключитесь на «Бизнес» и откройте «Создать задачу».
2. Введите: «Хотим автоматизировать первую линию технической поддержки».
3. Ответьте на три вопроса, дополните слабые поля, пересчитайте рейтинг, подтвердите и опубликуйте карточку.
4. Переключитесь на «Студент», найдите новую задачу в каталоге и отправьте предложение.
5. Вернитесь в роль «Бизнес», откройте задачу и нажмите «Выбрать» или «Отклонить».

## Ограничения MVP

- переключатель ролей заменяет регистрацию и RBAC;
- нет чата, уведомлений, загрузки файлов и рекомендаций;
- AI не выбирает команды и не принимает бизнес-решения;
- fallback использует эвристики и предназначен для устойчивой демонстрации;
- production hardening, аудит доступа и расширенная модерация выходят за рамки хакатонного MVP.
